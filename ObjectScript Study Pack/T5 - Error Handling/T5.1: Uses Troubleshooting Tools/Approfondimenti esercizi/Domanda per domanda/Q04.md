# T5.1 · Q04 — Perché HOROLOG non è un cronometro

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-4-single>)

## Il passaggio che risolve l’esercizio

L’aritmetica sulla coppia giorno,secondi usa il prefisso numerico e perde la parte oraria.

## Che cosa insegna in più

Il numero 66818 dichiarato nell’esempio non segue in generale dalla sottrazione di due letture: nello stesso giorno il prefisso può dare differenza zero. Il difetto resta l’uso della rappresentazione sbagliata.

## Prova a cambiare il caso

Una differenza zero prova che non sia passato tempo?

<details>
<summary>Ragionamento e risposta</summary>

No, se hai sottratto i soli prefissi del giorno.

</details>

## Testo dell’esercizio

```text
A developer benchmarks two approaches for processing 100,000 records:

Set start = $HOROLOG
For i=1:1:100000 { Do ##class(App.Record).Process(i) }
Set elapsed = $HOROLOG - start
Write "Elapsed: ", elapsed

The output shows: Elapsed: 66818. Why is this value unexpected?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-4-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** $HOROLOG is in date,seconds format and cannot be subtracted directly to get meaningful elapsed time

$HOROLOG returns a value in the format 'days,seconds' (e.g., '66818,45123'). When ObjectScript subtracts two such values, it treats them as numbers, truncating at the comma. The result is meaningless for timing purposes. The developer should use $ZH instead, which returns a single numeric value in seconds with fractional precision. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_vhorolog))

</details>
