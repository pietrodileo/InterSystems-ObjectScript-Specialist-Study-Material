# T5.2 · Q14 — Accumulare errori richiede indipendenza

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-14-single>)

## Il passaggio che risolve l’esercizio

ADDSC combina gli status per riferire più fallimenti, invece di fermarsi al primo.

## Che cosa insegna in più

Eseguire tutti gli import è sensato solo se le fasi successive non dipendono da un prerequisito fallito. Aggregare non risolve le dipendenze.

## Prova a cambiare il caso

Se ImportOrders richiede Customers validi, va sempre eseguito dopo un fallimento dei clienti?

<details>
<summary>Ragionamento e risposta</summary>

No, definisci la politica di arresto o recupero.

## Testo dell’esercizio

```text
A developer writes a method that wraps multiple %Status-returning calls:

ClassMethod ImportAll() As %Status
{
    Set sc = $$$OK
    Set sc = $$$ADDSC(sc, ..ImportCustomers())
    Set sc = $$$ADDSC(sc, ..ImportOrders())
    Set sc = $$$ADDSC(sc, ..ImportProducts())
    Quit sc
}

What does $$$ADDSC do?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-14-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Appends the new status to sc, combining multiple errors into a single %Status

$$$ADDSC (Add Status Code) appends a new %Status to an existing one, combining multiple errors into a single compound %Status value. This allows the method to attempt all three imports and report all failures together rather than stopping at the first error. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_status))

</details>
