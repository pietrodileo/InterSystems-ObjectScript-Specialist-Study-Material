# T5.2 · Q10 — Catturare selettivamente

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-10-single>)

## Il passaggio che risolve l’esercizio

Il CATCH gestisce il caso noto e rilancia ex per gli altri, mantenendo la possibilità di gestione esterna.

## Che cosa insegna in più

Registrare un errore non equivale a recuperarlo. Se non puoi completare l’operazione, propaga il fallimento anziché continuare silenziosamente.

## Prova a cambiare il caso

Un catch che scrive solo un messaggio e prosegue è sempre corretto?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

## Testo dell’esercizio

```text
A developer needs to catch only specific errors and re-throw others:

TRY {
    Do ..RiskyOperation()
} CATCH ex {
    If ex.Name = "<STORE>" {
        // handle storage error
        Set sc = ..HandleStorageError(ex)
    } Else {
        // What goes here to re-throw the exception?
    }
}
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-10-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** throw ex

The 'throw' command re-throws an exception object, allowing it to propagate to an outer TRY-CATCH block. This is the standard pattern for selectively catching certain exceptions while letting others propagate up the call stack. 'Quit' would exit the CATCH block, 'return' would return from the method, and 'raise' is not an ObjectScript command. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_cthrow))

</details>
