# T5.2 · Q01 — Stack corrente e contesto dell’errore

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

PLACE descrive le posizioni dei frame disponibili. La fonte semplifica $STACK(-1) come profondità corrente.

## Che cosa insegna in più

La documentazione distingue $STACK corrente e il massimo livello di contesto informativo con -1, specialmente durante la gestione dell’errore. Non assumere che il momento del logging coincida con quello del guasto.

## Prova a cambiare il caso

Una funzione di logging aggiunge il proprio contesto di chiamata?

<details>
<summary>Ragionamento e risposta</summary>

Sì: distinguilo dallo stack conservato dell’errore.

</details>

## Testo dell’esercizio

```text
Your application logs the following runtime error at random:

HandleOrder+4^Sample.Service.1 *orderId

You suspect that one of several upstream helper methods is passing an empty orderId. You want to modify HandleOrder() so that whenever an error occurs, it prints the full call stack.

Which technique lets you capture and display that call-stack information?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: D.** Invoke the $STACK function in a loop to iterate and print upstream methods

$STACK(-1) returns the current call stack depth, and $STACK(level, "PLACE") returns the location at each level. By looping from 0 to $STACK(-1), you can print every method in the call chain that led to the error. $ZERROR only gives the most recent error string, not the full call stack. This matches InterSystems practice question Q22. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fstack))

</details>
