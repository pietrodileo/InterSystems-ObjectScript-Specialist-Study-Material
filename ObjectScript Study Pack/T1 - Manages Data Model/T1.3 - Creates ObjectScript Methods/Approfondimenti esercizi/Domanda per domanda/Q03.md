# T1.3 · Q03 — Arrotondamento al confine dell’operazione

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-3-single>)

## Il passaggio che risolve l’esercizio

Add somma 1.123456 e 2.654321 ottenendo 3.777777; Round formatta a quattro decimali producendo 3.7778.

## Che cosa insegna in più

Arrotondare ogni addendo prima di sommare può differire dall’arrotondamento finale. Decidi il punto del calcolo in base al contratto numerico.

## Prova a cambiare il caso

Con due importi da 0.005 e due decimali, è indifferente arrotondare prima o dopo la somma?

<details>
<summary>Ragionamento e risposta</summary>

No: il punto di arrotondamento può cambiare il risultato.

</details>

## Testo dell’esercizio

```text
Consider the following class.

Class App.Calculator Extends %RegisteredObject
{
Parameter PRECISION = 4;

ClassMethod Round(value As %Numeric) As %Numeric
{
  return $FN(value, "", ..#PRECISION)
}

ClassMethod Add(a As %Numeric, b As %Numeric) As %Numeric
{
  return ..Round(a + b)
}
}

A developer runs:

write ##class(App.Calculator).Add(1.123456, 2.654321)

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-3-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 3.7778

Class methods CAN call other class methods in the same class using the .. syntax. The Add() method calls ..Round(3.777777), and Round() uses $FN with the PRECISION parameter value of 4 to format the number to 4 decimal places, resulting in 3.7778. The ..# syntax accesses the parameter, and the .. syntax calls the class method \-- both work from within a class method. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_methods))

</details>
