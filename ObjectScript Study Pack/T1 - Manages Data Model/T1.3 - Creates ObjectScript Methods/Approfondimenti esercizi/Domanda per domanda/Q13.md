# T1.3 · Q13 — Parametro ereditato specializzato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-13-single>)

## Il passaggio che risolve l’esercizio

AuditLogger eredita Log ma sostituisce LOGPREFIX: la chiamata dell’esempio risolve AUDIT nel contesto della sottoclasse.

## Che cosa insegna in più

Un algoritmo ereditato può essere specializzato tramite parametri senza duplicare il corpo del metodo.

## Prova a cambiare il caso

Se vuoi cambiare anche la destinazione del log, basta cambiare il prefisso?

<details>
<summary>Ragionamento e risposta</summary>

No: quella modifica non cambia il comportamento di scrittura.

</details>

## Testo dell’esercizio

```text
Consider the following class.

Class App.Logger Extends %RegisteredObject
{
Parameter LOGPREFIX = "APP";

ClassMethod Log(message As %String)
{
  write "[" _ ..#LOGPREFIX _ "] " _ message, !
}
}

Class App.AuditLogger Extends App.Logger
{
Parameter LOGPREFIX = "AUDIT";
}

A developer runs:

do ##class(App.AuditLogger).Log("User logged in")

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-13-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** \[AUDIT\] User logged in

App.AuditLogger inherits the Log() method from App.Logger. When Log() is called on App.AuditLogger, the ..#LOGPREFIX reference resolves to the parameter value defined in App.AuditLogger, which is "AUDIT". Parameters can be overridden in subclasses, and ..# always resolves to the value in the class the method is being called on, not the class where the method was originally defined. This is a form of parametric polymorphism. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_parameters))

</details>
