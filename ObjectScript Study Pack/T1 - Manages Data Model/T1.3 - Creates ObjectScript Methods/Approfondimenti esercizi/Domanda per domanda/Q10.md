# T1.3 · Q10 — Stato che sopravvive tra chiamate

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-10-single>)

## Il passaggio che risolve l’esercizio

L’istanza parte da zero e accumula +1, +5, +1: i ritorni sono 1, 6, 7.

## Che cosa insegna in più

Il default riguarda l’argomento omesso, non il ripristino della proprietà. Una nuova istanza ha invece un proprio stato iniziale.

## Prova a cambiare il caso

Dopo le tre chiamate, una seconda istanza appena creata con Increment() ritorna 8?

<details>
<summary>Ragionamento e risposta</summary>

No: nello scenario ritorna 1.

</details>

Visual connection: Core mechanisms, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following code.

Class App.Counter Extends %RegisteredObject
{
Property Value As %Integer [ InitialExpression = 0 ];

Method Increment(amount As %Integer = 1) As %Integer
{
  set ..Value = ..Value + amount
  return ..Value
}
}

// Caller:
set c = ##class(App.Counter).%New()
write c.Increment(), " "
write c.Increment(5), " "
write c.Increment()

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-10-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 1 6 7

The method signature includes a default value: amount As %Integer \= 1\. When called without arguments, amount defaults to 1\. First call: 0\+1\=1, returns 1\. Second call: 1\+5\=6, returns 6\. Third call: 6\+1\=7, returns 7\. The Value property persists across calls because the method modifies the instance state via ..Value. Default argument values allow flexible method signatures. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_methods))

</details>
