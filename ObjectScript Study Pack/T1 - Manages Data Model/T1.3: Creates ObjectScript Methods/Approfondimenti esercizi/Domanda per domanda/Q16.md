# T1.3 · Q16 — Algoritmo comune e passaggio specializzato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-16-single>)

## Il passaggio che risolve l’esercizio

Process chiama FetchData sull’istanza reale FileSource e trasforma il testo restituito in maiuscolo.

## Che cosa insegna in più

La base definisce la sequenza; la sottoclasse fornisce un passaggio. Il riuso funziona finché l’implementazione specializzata rispetta il valore atteso dal chiamante.

## Prova a cambiare il caso

Se FetchData iniziasse a restituire uno status invece del testo, Process sarebbe ancora corretto?

<details>
<summary>Ragionamento e risposta</summary>

No: cambierebbe il contratto del passaggio.

</details>

## Testo dell’esercizio

```text
Consider the following class with an abstract method.

Class App.DataSource Extends %RegisteredObject [ Abstract ]
{
Method FetchData() As %String [ Abstract ]
{
}

Method Process() As %String
{
  set raw = ..FetchData()
  return $ZCONVERT(raw, "U")
}
}

Class App.FileSource Extends App.DataSource
{
Method FetchData() As %String
{
  return "data from file"
}
}

A developer runs:

set src = ##class(App.FileSource).%New()
write src.Process()

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-16-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** "DATA FROM FILE"

The Process() method calls ..FetchData(). Since the actual object is an App.FileSource instance, its FetchData() implementation runs, returning "data from file". Process() then passes this through $ZCONVERT with "U" to convert to uppercase, resulting in "DATA FROM FILE". This demonstrates the Template Method design pattern: the base class defines the algorithm (Process) while subclasses provide specific implementations (FetchData). (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_methods))

</details>
