# T1.2 · Q01 — MAXLEN è un contratto da controllare

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

Il punto utile è rendere esplicita la lunghezza richiesta e controllare la validazione; il troncamento silenzioso descritto dalla fonte non va assunto come comportamento universale.

## Che cosa insegna in più

Un Bio di migliaia di caratteri e un report di megabyte hanno esigenze diverse: aumentare il limite non rende una stringa equivalente a uno stream.

## Prova a cambiare il caso

Per un campo di 2000 caratteri, cosa proveresti al confine?

<details>
<summary>Ragionamento e risposta</summary>

Valori di 1999, 2000 e 2001 caratteri e lo status ottenuto.

</details>

Visual connection: Core mechanisms, panel 1; Further insights, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer defines the following class.

Class App.Contact Extends %Persistent
{
Property FirstName As %String;
Property LastName As %String;
Property Bio As %String;
}

After deploying, users report that bios longer than 50 characters are being silently truncated. Which of the following explains the issue and provides the correct fix?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** The default MAXLEN for %String is 50\. The fix is: Property Bio As %String(MAXLEN \= 2000);

The default MAXLEN for %String properties in InterSystems IRIS is 50 characters. When data exceeds MAXLEN, it may be truncated during validation or storage. The fix is to explicitly set MAXLEN to a value that accommodates the expected data size. For very large text (megabytes), a stream type should be used instead. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_datatypes))

</details>
