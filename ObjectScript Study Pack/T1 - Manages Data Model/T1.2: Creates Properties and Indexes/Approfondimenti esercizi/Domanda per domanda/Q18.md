# T1.2 · Q18 — Nessun MAXLEN non significa infinito

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-18-single>)

## Il passaggio che risolve l’esercizio

MAXLEN vuoto rimuove quel controllo di lunghezza, ma rimangono i limiti delle stringhe della piattaforma e del contesto.

## Che cosa insegna in più

La decisione tra stringa e stream riguarda anche elaborazione, memoria e interfaccia, non soltanto il limite di validazione.

## Prova a cambiare il caso

Un import di centinaia di megabyte diventa adatto a %String impostando MAXLEN vuoto?

<details>
<summary>Ragionamento e risposta</summary>

No: usa un flusso e una strategia a blocchi.

</details>

## Testo dell’esercizio

```text
Consider the following class.

Class App.Metric Extends %Persistent
{
Property Name As %String(MAXLEN = "");
Property Value As %Numeric;
}

What does MAXLEN = "" mean for the Name property?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-18-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** It removes the length limit entirely, allowing the property to hold a string of any length up to the maximum string size

Setting MAXLEN to an empty string (MAXLEN \= "") removes the length validation constraint entirely, allowing the property to hold any string up to the maximum string size supported by the system (approximately 3.6 million characters). This is useful when you need strings larger than the default 50 characters but do not want to pick an arbitrary limit. However, for very large text content, streams are still recommended. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_datatypes))

</details>
