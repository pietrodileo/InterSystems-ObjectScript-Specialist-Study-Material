# T1.2 · Q17 — Timestamp iniziale e unicità

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-17-single>)

## Il passaggio che risolve l’esercizio

L’espressione viene valutata alla creazione e fotografa quell’istante. Non è un timestamp congelato alla compilazione.

## Che cosa insegna in più

Un valore temporale non garantisce un identificatore univoco: due oggetti possono nascere nella stessa risoluzione dell’orologio. La fonte usa unico in modo troppo forte.

## Prova a cambiare il caso

Due Task creati nello stesso secondo possono avere lo stesso CreatedAt?

<details>
<summary>Ragionamento e risposta</summary>

Sì; serve un altro meccanismo se occorre unicità.

</details>

## Testo dell’esercizio

```text
Consider the following class.

Class App.Task Extends %Persistent
{
Property Title As %String(MAXLEN = 200);
Property AssignedTo As %String(MAXLEN = 100);
Property Priority As %Integer;
Property CreatedAt As %TimeStamp [ InitialExpression = {$ZDT($H, 3)} ];
}

What is special about the InitialExpression for CreatedAt?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-17-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** The curly braces indicate the expression is evaluated at runtime when %New() is called, so each new object gets the current timestamp

When an InitialExpression is enclosed in curly braces { }, it is treated as an ObjectScript expression that is evaluated at runtime each time %New() is called. Without curly braces, the value would be a static literal. So {$ZDT($H, 3)} evaluates $ZDT($H, 3\) at object creation time, giving each new Task its own unique timestamp reflecting when it was created. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_datatypes))

</details>
