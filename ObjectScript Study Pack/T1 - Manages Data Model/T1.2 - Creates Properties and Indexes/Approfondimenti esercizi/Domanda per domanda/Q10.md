# T1.2 · Q10 — Parametro e configurazione applicativa

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-10-single>)

## Il passaggio che risolve l’esercizio

APPVERSION si legge con # e non con la sintassi di una proprietà d’istanza. Non serve creare un oggetto per accedere al parametro.

## Che cosa insegna in più

Un parametro di classe esprime un valore nella definizione compilata; una configurazione modificabile dagli utenti ha requisiti di aggiornamento differenti.

## Prova a cambiare il caso

Cambiare una riga di configurazione applicativa cambia da solo #APPVERSION?

<details>
<summary>Ragionamento e risposta</summary>

No: sono meccanismi diversi.

</details>

## Testo dell’esercizio

```text
Consider the following class.

Class App.Config Extends %Persistent
{
Parameter DEFAULTMAXLEN = 200;
Parameter APPVERSION = "3.2.1";

Property Setting As %String;
Property Value As %String;
}

A developer writes:

write ##class(App.Config).#APPVERSION

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-10-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 3.2.1

Class parameters can be accessed from outside the class using the ##class(ClassName).#ParameterName syntax. From inside the class, both ..#ParameterName and ##class(ClassName).#ParameterName work. Parameters are compile-time constants that are accessible from both instance methods and class methods. The output is the string 3.2.1 without quotes. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_parameters))

</details>
