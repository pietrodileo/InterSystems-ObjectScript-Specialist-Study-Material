# T1.2 · Q16 — Assegnazione e validazione

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-16-single>)

## Il passaggio che risolve l’esercizio

Salary 25000 può essere assegnato all’oggetto, ma viola MINVAL 30000 quando viene validato dal save. $$$ISOK restituisce quindi falso nello scenario.

## Che cosa insegna in più

Separare lo stato temporaneo in memoria dallo stato accettabile per la persistenza spiega perché controllare il SET non basta.

## Prova a cambiare il caso

Con MINVAL 30000, qual è il primo valore di confine valido?

<details>
<summary>Ragionamento e risposta</summary>

30000, se non intervengono altri vincoli.

</details>

## Testo dell’esercizio

```text
Consider the following class that uses a property parameter constraint.

Class App.Employee Extends %Persistent
{
Property Name As %String(MAXLEN = 100);
Property Salary As %Numeric(MINVAL = 30000, MAXVAL = 500000, SCALE = 2);
Property Department As %String(MAXLEN = 50);
}

A developer runs:

set emp = ##class(App.Employee).%New()
set emp.Name = "Jane Doe"
set emp.Salary = 25000
set emp.Department = "Engineering"
set sc = emp.%Save()
write $$$ISOK(sc)

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-16-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 0 \-- the save fails because Salary \= 25000 violates the MINVAL \= 30000 constraint

MINVAL and MAXVAL are validation constraints that are enforced during %Save(). When Salary is set to 25000, which is below the MINVAL of 30000, the validation check fails and %Save() returns an error %Status. $$$ISOK(sc) returns 0 (false) because the status indicates failure. These constraints are enforced in both ObjectScript and SQL contexts. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_datatypes))

</details>
