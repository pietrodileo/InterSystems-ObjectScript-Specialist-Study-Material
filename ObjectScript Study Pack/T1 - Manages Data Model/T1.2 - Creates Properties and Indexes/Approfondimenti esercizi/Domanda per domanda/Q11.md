# T1.2 · Q11 — Ordine delle chiavi composte

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

SensorId restringe la prima parte dell’indice; dentro quel gruppo ReadingTime consente la scansione dell’intervallo.

## Che cosa insegna in più

L’ordine dei predicati scritti nel WHERE non cambia l’ordine fisico dell’indice. Conta l’ordine nella definizione delle chiavi.

## Prova a cambiare il caso

Invertire i due predicati nel testo SQL distrugge il vantaggio?

<details>
<summary>Ragionamento e risposta</summary>

No: non equivale a invertire le colonne dell’indice.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 4. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following class.

Class App.Sensor Extends %Persistent
{
Property SensorId As %String;
Property Temperature As %Numeric;
Property Humidity As %Numeric;
Property ReadingTime As %TimeStamp;

Index SensorTimeIdx On (SensorId, ReadingTime);
}

Which of the following queries would best benefit from the compound index SensorTimeIdx?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** SELECT \* FROM App.Sensor WHERE SensorId \= 'S100' AND ReadingTime \> '2026-01-01'

A compound index on (SensorId, ReadingTime) is organized first by SensorId, then by ReadingTime within each SensorId. This makes it optimal for queries that filter on SensorId (the leading key) and then range-scan on ReadingTime. The query in option C filters on both fields in the correct order. A query on only ReadingTime (option B) cannot efficiently use this index because ReadingTime is not the leading key. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GSQL_tables))

</details>
