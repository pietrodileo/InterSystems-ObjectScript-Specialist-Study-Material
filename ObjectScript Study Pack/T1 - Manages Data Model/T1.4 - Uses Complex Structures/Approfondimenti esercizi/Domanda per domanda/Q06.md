# T1.4 · Q06 — Alias di un array annidato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-6-single>)

## Il passaggio che risolve l’esercizio

arr e obj.values puntano allo stesso DynamicArray; %Set(1,99) cambia il secondo elemento visto da entrambi.

## Che cosa insegna in più

Assegnare una variabile non significa clonare un grafo di oggetti. La condivisione è utile ma può produrre modifiche indirette inattese.

## Prova a cambiare il caso

Se vuoi una variante indipendente dell’ordine, basta set copia=ordine?

<details>
<summary>Ragionamento e risposta</summary>

No: serve una strategia esplicita di copia adeguata alla struttura.

</details>

## Testo dell’esercizio

```text
Consider the following code.

set obj = {"name": "Test", "values": [10, 20, 30]}
set arr = obj.values
do arr.%Set(1, 99)
write obj.%ToJSON()

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-6-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** {"name":"Test","values":\[10,99,30\]} \-- arr references the same array object

When you access obj.values, you receive a reference to the same %DynamicArray object \-- not a copy. Modifying it through the arr variable (setting index 1 to 99\) directly modifies the array inside obj. %DynamicArray is zero-indexed, so %Set(1, 99\) replaces the element at index 1 (which was 20\) with 99\. The result is \[10, 99, 30\]. This is consistent with how object references work in ObjectScript. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GJSON_create))

</details>
