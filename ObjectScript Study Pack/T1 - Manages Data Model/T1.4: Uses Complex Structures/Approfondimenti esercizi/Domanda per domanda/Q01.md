# T1.4 · Q01 — Due parser, due significati di true

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

Nel SET ordinario true è un nome di variabile; nel letterale JSON è un booleano del linguaggio JSON.

## Che cosa insegna in più

Il contesto sintattico decide il significato. Impostare 1 senza indicare il tipo non documenta necessariamente un booleano nella risposta serializzata.

## Prova a cambiare il caso

Come produci esplicitamente un booleano JSON?

<details>
<summary>Ragionamento e risposta</summary>

Con %Set della proprietà usando il tipo boolean, oppure con un letterale JSON valido.

</details>

## Testo dell’esercizio

```text
Consider the following code.

set patient = {}
set patient.name = "Alice Smith"
set patient.age = 34
set patient.active = true
write patient.%ToJSON()

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** An \<UNDEFINED\> error on the line set patient.active \= true

In ObjectScript, 'true' is not a keyword or literal \-- it is interpreted as a variable name. Since no variable named 'true' has been defined, the SET command raises an \<UNDEFINED\> \*true error. To set a JSON boolean, you must either use the %Set method with a type parameter: do patient.%Set("active", 1, "boolean"), or use the JSON literal syntax: set patient \= {"active": true}. The JSON literal parser recognizes true/false/null, but the ObjectScript language itself does not. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GJSON_create))

</details>
