# T1.4 · Q08 — JSON grande e costo del consumatore

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-8-single>)

## Il passaggio che risolve l’esercizio

La serializzazione nello stream evita di restituire subito una singola stringa; Rewind rende esplicito l’inizio della lettura.

## Che cosa insegna in più

Il ciclo del quiz ricompone poi l’intero JSON in memoria: questo perde parte del vantaggio per documenti grandi. Anche il consumatore deve lavorare a blocchi.

## Prova a cambiare il caso

Se il JSON occupa centinaia di megabyte, conviene accumulare json=json_chunk più volte in una stringa?

<details>
<summary>Ragionamento e risposta</summary>

No: mantieni una pipeline a flusso quando possibile.

</details>

Visual connection: Core mechanisms, panel 3. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following code that writes JSON to a stream.

set report = {"title": "Monthly Report", "items": [1, 2, 3]}
set stream = ##class(%Stream.GlobalCharacter).%New()
do report.%ToJSON(stream)
do stream.Rewind()
set json = ""
while 'stream.AtEnd {
  set json = json _ stream.Read()
}
write json

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-8-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** {"title":"Monthly Report","items":\[1,2,3\]}

%ToJSON() can accept an optional stream argument. When a stream is passed, the JSON output is written directly to the stream instead of being returned as a string. This is more memory-efficient for large objects. After writing, Rewind() resets the read position to the beginning, and the while loop reads all the data. The stream does not need to be saved to a persistent object to be used in memory. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GJSON_create))

</details>
