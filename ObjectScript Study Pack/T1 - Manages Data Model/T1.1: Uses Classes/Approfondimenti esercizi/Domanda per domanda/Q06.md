# T1.1 · Q06 — Caricamento e riferimento valido

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-6-single>)

## Il passaggio che risolve l’esercizio

%OpenId produce un oref oppure una stringa vuota nel caso non trovato. Accedere subito a Salary confonde caricamento e uso dell’oggetto.

## Che cosa insegna in più

Il controllo dell’esistenza va prima di qualsiasi dereferenziazione. Lo status di uscita consente inoltre una diagnosi più precisa.

## Prova a cambiare il caso

Se l’ID manca, un successivo SET emp.Salary crea automaticamente il dipendente?

<details>
<summary>Ragionamento e risposta</summary>

No: manca il riferimento su cui operare.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer writes the following code:

set emp = ##class(HR.Employee).%OpenId(42)
if emp = "" {
  write "Employee not found",!
  quit
}
set emp.Salary = 75000
set sc = emp.%Save()

Which of the following is true about %OpenId()?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-6-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** %OpenId() returns an object reference (oref) on success, or an empty string if the ID does not exist

%OpenId() is a class method that loads a persistent object from disk by its integer ID. It returns an oref (object reference) if the ID exists, or an empty string ("") if not found. It does not throw exceptions or return %Status by default. The developer must check for an empty return before accessing properties to avoid \<INVALID OREF\> errors. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_persobj))

</details>
