# T1.1 · Q07 — Cancellazione con effetti applicativi

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-7-single>)

## Il passaggio che risolve l’esercizio

%DeleteExtent è la scelta del quiz quando servono le callback di cancellazione. DROP TABLE cambia anche lo schema, mentre la cancellazione rapida segue un contratto diverso.

## Che cosa insegna in più

Prima di ottimizzare una cancellazione chiediti quali verifiche o effetti implementano le callback: la stessa quantità di righe eliminate non implica lo stesso comportamento.

## Prova a cambiare il caso

Se una callback aggiorna un registro, basta verificare che la tabella sia vuota?

<details>
<summary>Ragionamento e risposta</summary>

No: va verificato anche l’effetto previsto dal registro.

</details>

## Testo dell’esercizio

```text
Consider the following class.

Class Lab.Experiment Extends %Persistent
{
Property Title As %String;
Property Researcher As %String;
}

A developer wants to delete all experiment records. Which of the following approaches deletes all records AND properly fires any %OnDelete callbacks?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-7-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** set sc \= ##class(Lab.Experiment).%DeleteExtent()

%DeleteExtent() iterates through all instances and deletes each one individually, which ensures that %OnDelete callbacks are fired for every record. %KillExtent() is faster but simply kills the globals directly without firing callbacks. DROP TABLE removes the table definition entirely, not just the data. %DeleteExtent() returns a %Status value indicating overall success or failure. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_persobj))

</details>
