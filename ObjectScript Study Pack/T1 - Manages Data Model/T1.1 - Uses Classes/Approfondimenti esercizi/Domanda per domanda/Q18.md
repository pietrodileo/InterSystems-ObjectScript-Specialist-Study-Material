# T1.1 · Q18 — Visitare record esistenti

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-18-single>)

## Il passaggio che risolve l’esercizio

Il ciclo prova mille identificativi ma può trovare soltanto cinquecento oggetti. L’intervallo visitato non coincide con l’insieme delle righe presenti.

## Che cosa insegna in più

La spiegazione del quiz propone una possibile distribuzione, non una prova di quali ID manchino. Conta caricati, mancanti, falliti e salvati per distinguere le cause.

## Prova a cambiare il caso

Se mancano gli ID dispari anziché quelli sopra 500, il totale può restare 500?

<details>
<summary>Ragionamento e risposta</summary>

Sì: lo stesso totale non identifica la distribuzione dei buchi.

</details>

Visual connection: Core mechanisms, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following code that a developer uses to manage a batch process.

set sc = $$$OK
for id = 1:1:1000 {
  set obj = ##class(Batch.Record).%OpenId(id)
  if obj '= "" {
    set obj.Processed = 1
    set sc = obj.%Save()
    if $$$ISERR(sc) quit
  }
}
if $$$ISERR(sc) {
  do $SYSTEM.Status.DisplayError(sc)
}

The developer notices that only 500 records have Processed = 1, despite the loop iterating over IDs 1 through 1000. There was no error displayed.

Which of the following best explains this behavior?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-18-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** The %OpenId() call returns empty string for IDs above 500, and the if obj '\= "" check skips them silently

If %OpenId() returns empty string for IDs 501-1000, the if obj '\= "" check causes those iterations to be silently skipped with no error. This could happen if IDs 501-1000 were deleted previously (remember, the ID counter can go higher than existing records). The developer should add logging for the case when obj is empty to detect missing records. There is no limit on the number of %Save() calls per process. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GOBJ_persobj))

</details>
