# T3.3 · Q08 — NUL come delimitatore reale

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-8-single>)

## Il passaggio che risolve l’esercizio

Il carattere zero separa i tre campi e $PIECE estrae Doe dalla seconda posizione.

## Che cosa insegna in più

Un delimitatore raro riduce alcune collisioni ma non garantisce che il dato non possa contenerlo. Il formato deve prevedere come trattare quel caso.

## Prova a cambiare il caso

Se un campo può contenere NUL, il semplice delimitatore è sempre reversibile?

<details>
<summary>Ragionamento e risposta</summary>

No, serve una codifica o struttura che preservi i confini.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer stores data using $CHAR(0) as a delimiter:

set record = "John" _ $CHAR(0) _ "Doe" _ $CHAR(0) _ "Boston"
write $PIECE(record, $CHAR(0), 2)

What is displayed?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-8-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** Doe

$CHAR(0) is a valid single character (NUL, ASCII 0\) and works perfectly as a delimiter in $PIECE. It is commonly used as a delimiter because it rarely appears in actual data. The second piece of the record is "Doe". This demonstrates that $CHAR(0) is a real character, not equivalent to empty string or NULL. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fpiece))

</details>
