# T3.3 · Q02 — Rappresentazione SQL e ObjectScript

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-2-single>)

## Il passaggio che risolve l’esercizio

Nella proprietà persistente mostrata, il valore ObjectScript vuoto viene proiettato come SQL NULL.

## Che cosa insegna in più

La parola vuoto va accompagnata dal livello: stringa vuota ObjectScript e stringa SQL di lunghezza zero non sono la stessa rappresentazione.

## Prova a cambiare il caso

Per cercare quel valore in SQL usi =NULL?

<details>
<summary>Ragionamento e risposta</summary>

No: usa IS NULL.

</details>

## Testo dell’esercizio

```text
A developer sets a property to empty string in ObjectScript and then queries it via SQL:

set obj = ##class(Sample.Person).%OpenId(1)
set obj.Email = ""
set sc = obj.%Save()

// Later, via SQL:
&sql(SELECT COUNT(*) INTO :cnt FROM Sample.Person WHERE Email IS NULL AND ID = 1)
write cnt
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-2-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 1 \- the empty string in ObjectScript maps to NULL in SQL

In InterSystems IRIS, the ObjectScript empty string "" IS the representation of SQL NULL. Setting a property to "" (or leaving it unset, since "" is the default) projects as SQL NULL, so IS NULL matches the row and cnt \= 1\. The SQL zero-length string '' is the ObjectScript value $CHAR(0), which is a distinct value of length 1 and does NOT match IS NULL (it matches \= ''). (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GSQL_langelements#GSQL_langelements_null))

</details>
