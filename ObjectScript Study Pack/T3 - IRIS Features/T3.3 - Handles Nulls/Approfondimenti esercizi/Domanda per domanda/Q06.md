# T3.3 · Q06 — COALESCE non scarta stringhe SQL vuote

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-6-single>)

## Il passaggio che risolve l’esercizio

Phone='' è un valore non NULL, quindi viene scelto prima dell’email.

## Che cosa insegna in più

Se il requisito applicativo considera inutilizzabili anche stringhe vuote o spazi, occorre normalizzarle esplicitamente prima del fallback.

## Prova a cambiare il caso

Per far passare COALESCE all’email basta che Phone appaia vuoto sullo schermo?

<details>
<summary>Ragionamento e risposta</summary>

No, deve essere NULL secondo SQL.

</details>

## Testo dell’esercizio

```text
A developer writes a SQL query with COALESCE:

&sql(SELECT COALESCE(Phone, Email, 'No Contact') INTO :contact
     FROM Sample.Person WHERE ID = :id)

If the row has Phone = '' and Email = 'user@test.com', what value does :contact hold?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-6-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** '' (empty string)

In InterSystems IRIS, SQL '' (zero-length string) is NOT the same as SQL NULL. COALESCE returns the first non-NULL argument. Since Phone \= '' is a zero-length string (not NULL), COALESCE returns '' immediately without checking Email or the fallback. To make COALESCE skip Phone, it would need to be NULL (represented in ObjectScript by the empty string ""), not the SQL zero-length string (represented in ObjectScript by $CHAR(0)). (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RSQL_coalesce))

</details>
