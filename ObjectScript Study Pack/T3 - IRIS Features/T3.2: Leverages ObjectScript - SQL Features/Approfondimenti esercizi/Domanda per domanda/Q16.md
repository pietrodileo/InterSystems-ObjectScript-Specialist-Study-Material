# T3.2 · Q16 — Esito e cardinalità dell’UPDATE

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-16-single>)

## Il passaggio che risolve l’esercizio

SQLCODE zero indica esecuzione riuscita e %ROWCOUNT riporta le cinquanta righe interessate nello scenario.

## Che cosa insegna in più

Un UPDATE riuscito con zero righe non è lo stesso fatto applicativo di un UPDATE riuscito con una riga. Il servizio può richiedere una cardinalità precisa.

## Prova a cambiare il caso

Per aggiornare un unico account, basta controllare SQLCODE=0?

<details>
<summary>Ragionamento e risposta</summary>

No: verifica anche il numero di righe atteso.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer writes the following embedded SQL:

&sql(UPDATE Sample.Person SET Status = 'Inactive' WHERE City = 'Boston')
write "Rows updated: ", %ROWCOUNT, !
write "SQLCODE: ", SQLCODE, !

If 50 rows have City = 'Boston', what output is produced?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-16-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Rows updated: 50, SQLCODE: 0

After a successful UPDATE, SQLCODE \= 0 indicates success and %ROWCOUNT contains the number of rows affected (50). SQLCODE \= 100 is for 'no data found' in SELECT queries, not for UPDATE. %ROWCOUNT always reflects the actual count of modified rows, not just 0 or 1\. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RSQL_variables))

</details>
