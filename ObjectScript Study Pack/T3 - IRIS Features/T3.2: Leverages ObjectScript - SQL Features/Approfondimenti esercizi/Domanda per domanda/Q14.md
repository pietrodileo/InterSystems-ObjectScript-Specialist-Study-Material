# T3.2 · Q14 — FETCH e conteggio delle righe ricevute

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-14-single>)

## Il passaggio che risolve l’esercizio

Dopo cinque FETCH riusciti, il FETCH finale senza dati non porta il conteggio a sei.

## Che cosa insegna in più

La fine del cursore è un evento di controllo, non una riga. Elabora solo dopo aver verificato il risultato del FETCH.

## Prova a cambiare il caso

Incrementare il contatore prima di controllare SQLCODE può creare un errore di uno?

<details>
<summary>Ragionamento e risposta</summary>

Sì.

</details>

## Testo dell’esercizio

```text
A developer writes a cursor-based query:

&sql(DECLARE personCursor CURSOR FOR
     SELECT Name, City FROM Sample.Person WHERE Status = 'Active')
&sql(OPEN personCursor)
set count = 0
for {
    &sql(FETCH personCursor INTO :name, :city)
    quit:SQLCODE'=0
    set count = count + 1
}
&sql(CLOSE personCursor)
write "Processed: ", count, " rows. ROWCOUNT: ", %ROWCOUNT

If 5 rows match, what does %ROWCOUNT contain after the loop?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-14-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 5

After a cursor FETCH loop, %ROWCOUNT contains the number of rows successfully fetched. The final FETCH that sets SQLCODE \= 100 (no more data) does not increment %ROWCOUNT. So %ROWCOUNT \= 5, matching the count variable. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RSQL_variables#RSQL_variables_rowcount))

</details>
