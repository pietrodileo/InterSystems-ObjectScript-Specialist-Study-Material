# T3.2 · Q06 — Dipendenza esplicita dalle macro standard

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-6-single>)

## Il passaggio che risolve l’esercizio

$$$OK deve essere definita nel contesto di compilazione. L’include della classe rende disponibili le macro previste.

## Che cosa insegna in più

Non correggere un errore di preprocessore cambiando il valore restituito a caso: preserva il contratto %Status e ripristina la dipendenza mancante.

## Prova a cambiare il caso

Se il nome di una macro contiene un refuso, aggiungere un include corretto risolve sempre?

<details>
<summary>Ragionamento e risposta</summary>

No: deve esistere proprio quella definizione.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 4. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer writes the following class:

Class MyApp.Utils Extends %RegisteredObject
{

ClassMethod Calculate() As %Status
{
    // business logic
    return $$$OK
}

}

The class fails to compile with an error about $$$OK being an undefined macro. What is the fix?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-6-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Add Include %occInclude at the class level

$$$OK is a macro defined in the %occInclude include file (which itself includes %occStatus). The class-level keyword is 'Include' (placed before the Class keyword), not '#Include' (which is a preprocessor directive used inside method bodies). Without an Include directive, the compiler cannot resolve the macro. Adding 'Include %occInclude' at the class level makes $$$OK, $$$ISERR, $$$ThrowOnError, and other standard macros available. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_macros#GCOS_macros_include))

</details>
