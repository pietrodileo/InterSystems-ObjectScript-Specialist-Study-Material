# T3.2 · Q07 — Non trovato non è errore SQL

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-7-single>)

## Il passaggio che risolve l’esercizio

SQLCODE 100 identifica il caso senza riga nel SELECT INTO; zero e valori negativi richiedono rami diversi.

## Che cosa insegna in più

Non usare il vecchio contenuto della variabile host come prova di una nuova riga dopo un SELECT senza risultato.

## Prova a cambiare il caso

Se x conteneva un dato prima del SELECT che non trova nulla, puoi stamparlo come risultato attuale?

<details>
<summary>Ragionamento e risposta</summary>

No: prima verifica SQLCODE.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following embedded SQL code:

&sql(SELECT Name, DOB INTO :name, :dob FROM Sample.Person WHERE ID = 999)
if SQLCODE = 0 {
    write "Found: ", name
} elseif SQLCODE = 100 {
    write "Not found"
} else {
    write "Error: ", SQLCODE
}

If no row with ID 999 exists, what is displayed?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-7-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Not found

When an embedded SQL SELECT INTO finds no matching rows, SQLCODE is set to 100\. SQLCODE \= 0 means successful execution with data returned. Negative SQLCODE values indicate actual errors. The code correctly checks for SQLCODE \= 100, so "Not found" is displayed. SQLCODE is automatically available as a local variable after any \&sql() statement. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RSQL_sqlcode))

</details>
