# T3.2 · Q08 — Modalità di selezione esplicita

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-8-single>)

## Il passaggio che risolve l’esercizio

Nel Dynamic SQL mostrato il default è logico: una %Date viene ricevuta come conteggio interno dei giorni.

## Che cosa insegna in più

Un numero che rappresenta una data non è una durata né un timestamp completo. Scegli il formato richiesto dall’interfaccia invece di affidarti all’aspetto stampato.

## Prova a cambiare il caso

Se il client richiede YYYY-MM-DD, basta restituire il numero logico?

<details>
<summary>Ragionamento e risposta</summary>

No, occorre la conversione appropriata.

</details>

## Testo dell’esercizio

```text
A developer writes the following dynamic SQL:

set stmt = ##class(%SQL.Statement).%New()
set sc = stmt.%Prepare("SELECT Name, DOB FROM Sample.Person WHERE City = ?")
set rs = stmt.%Execute("Boston")
while rs.%Next() {
    write rs.%Get("Name"), " - ", rs.%Get("DOB"), !
}

The DOB column is a %Date property. When using the default SelectMode, what format will DOB be displayed in?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-8-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** Logical format (e.g., 67339 \- integer days since 12/31/1840)

The default SelectMode for Dynamic SQL (%SQL.Statement) is Logical mode (mode 0). In Logical mode, %Date properties are returned as their internal integer representation (days since December 31, 1840). To get ODBC format, pass 1 to %New(): ##class(%SQL.Statement).%New(1). To get Display format, pass 2\. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RSQL_selectmode))

</details>
