# T3.1 · Q08 — Persistenza e journaling

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-8-single>)

## Il passaggio che risolve l’esercizio

Nel contesto mostrato il global applicativo in un database duraturo è il dato che rimane dopo il riavvio.

## Che cosa insegna in più

Persistenza dei dati e journaling sono proprietà collegate ma distinte: non affermare che un global sopravvive solo perché ogni database è sempre journaled.

## Prova a cambiare il caso

Un database duraturo con journaling disabilitato diventa automaticamente una PPG?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

## Testo dell’esercizio

```text
A developer examines the following code and needs to identify which variables will survive a system restart:

set localVar = "in memory"
set ^||processData = "process only"
set ^IRIS.Temp.shared = "temp shared"
set ^AppData("key") = "persistent"
set ^CacheTempWork(1) = "legacy temp"

Which variable will still contain data after a system restart?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-8-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: D.** ^AppData("key")

Only ^AppData("key") survives a restart because it is a persistent global stored in a journaled database. Local variables exist only in process memory. PPGs (^\|\|) are in IRISTEMP. ^IRIS.Temp.\* and ^CacheTemp\* globals are mapped to IRISTEMP. IRISTEMP is rebuilt on every restart, clearing all its contents. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_variables))

</details>
