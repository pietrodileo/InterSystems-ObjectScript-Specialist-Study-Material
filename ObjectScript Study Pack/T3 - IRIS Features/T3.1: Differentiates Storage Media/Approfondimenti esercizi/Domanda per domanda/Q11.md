# T3.1 · Q11 — Cambio di processo e identità del dato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

Il nuovo Terminal non recupera locali o PPG del precedente; il global persistente continua a essere consultabile nel mapping previsto.

## Che cosa insegna in più

Aprire una nuova finestra non è continuare lo stesso spazio locale di esecuzione. Il dato deve avere una durata compatibile con il passaggio.

## Prova a cambiare il caso

Il fatto che il nome x sia uguale ricrea il valore della sessione precedente?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

## Testo dell’esercizio

```text
Consider the following code executed in a Terminal session:

set x = 100
set ^data(1) = "saved"
set ^||temp = "processing"

The developer closes the Terminal (ending the process) and opens a new one. Which command will NOT produce an <UNDEFINED> error?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** write ^data(1)

When the Terminal process ends, local variable x and PPG ^\|\|temp are both destroyed. Only ^data(1), a persistent global, survives the process termination. In the new Terminal session, only write ^data(1) will return "saved" without error. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_variables))

</details>
