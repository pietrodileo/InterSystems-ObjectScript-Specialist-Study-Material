# T3.1 · Q03 — Stesso nome, contenitori diversi

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-3-single>)

## Il passaggio che risolve l’esercizio

B legge il proprio ^||counter, non quello creato da A. Se nel suo contesto manca, la lettura diretta è indefinita.

## Che cosa insegna in più

Non confondere l’isolamento con il blocco: B non attende che A liberi un dato, sta cercando un dato diverso.

## Prova a cambiare il caso

Usando $GET in B otterresti automaticamente il contatore di A?

<details>
<summary>Ragionamento e risposta</summary>

No: soltanto il default per il dato assente in B.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Process A executes the following code:

set ^||counter = 0
for i = 1:1:1000 {
    set ^||counter = ^||counter + 1
}
write ^||counter

Process B then executes:

write ^||counter

What happens in Process B?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-3-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** Process B gets an \<UNDEFINED\> error because ^\|\|counter does not exist in its context

Process-private globals are completely isolated per process. Process B has its own ^\|\|counter namespace, which was never set, so referencing it produces an \<UNDEFINED\> error. Even though both processes use the same name ^\|\|counter, these are entirely separate storage areas. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_variables#GCOS_variables_ppg))

</details>
