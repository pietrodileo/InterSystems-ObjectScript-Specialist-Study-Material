# T3.3 · Q11 — Aritmetica SQL e informazione mancante

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

Total-Discount restituisce NULL se Discount è NULL; nel contesto host illustrato arriva come stringa vuota.

## Che cosa insegna in più

Usare COALESCE(Discount,0) afferma una regola di dominio: sconto mancante significa nessuno sconto. Non è sempre la politica corretta.

## Prova a cambiare il caso

Se NULL significa sconto ancora da determinare, è corretto presentare subito il netto 100?

<details>
<summary>Ragionamento e risposta</summary>

Non senza decidere quella regola.

</details>

## Testo dell’esercizio

```text
Consider a table with nullable columns:

&sql(INSERT INTO Sample.Order (Total, Discount) VALUES (100, NULL))
set id = %ROWID
&sql(SELECT Total - Discount INTO :net FROM Sample.Order WHERE ID = :id)
write net
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** NULL — received as empty string in the host variable

In SQL, any arithmetic operation involving NULL returns NULL. 100 \- NULL \= NULL. This is standard SQL behavior and applies in InterSystems IRIS as well. When a NULL result is returned into an embedded SQL host variable, it is received as an empty string. To handle this, use COALESCE: Total \- COALESCE(Discount, 0). (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GSQL_langelements))

</details>
