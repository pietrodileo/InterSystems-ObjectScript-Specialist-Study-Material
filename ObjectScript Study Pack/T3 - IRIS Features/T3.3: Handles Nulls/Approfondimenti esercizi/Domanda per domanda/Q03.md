# T3.3 · Q03 — Esaminare i byte invisibili

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-3-single>)

## Il passaggio che risolve l’esercizio

Lunghezza 1 e codice 0 descrivono $CHAR(0); lunghezza 0 e $ASCII=-1 descrivono la stringa vuota nel caso illustrato.

## Che cosa insegna in più

Il valore -1 di $ASCII sul vuoto è un segnale convenzionale, non il codice di un carattere effettivamente presente.

## Prova a cambiare il caso

Se $ASCII restituisce 0, la stringa deve avere lunghezza zero?

<details>
<summary>Ragionamento e risposta</summary>

No: può contenere il carattere NUL.

</details>

Visual connection: Core mechanisms, panel 1; Further insights, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following ObjectScript code:

set x = $CHAR(0)
write $LENGTH(x), " "
write $ASCII(x), " "
write x = "", " "
write $LENGTH(""), " "
write $ASCII("")
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-3-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** 1 0 0 0 -1

$CHAR(0) has $LENGTH \= 1 (it is one character). $ASCII($CHAR(0)) \= 0 (the NUL character's ASCII code). $CHAR(0) \= "" is 0 (false, they are different). $LENGTH("") \= 0 (empty string). $ASCII("") \= -1 (the special return value for an empty string). These distinctions are critical for understanding null handling. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fchar))

</details>
