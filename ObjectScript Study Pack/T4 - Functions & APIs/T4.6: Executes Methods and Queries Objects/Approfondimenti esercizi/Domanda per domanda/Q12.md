# T4.6 · Q12 — Scrittura dinamica e validazione successiva

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-12-single>)

## Il passaggio che risolve l’esercizio

SET PROPERTY assegna Timeout=30 tramite un nome variabile.

## Che cosa insegna in più

La modifica dello stato in memoria non prova il salvataggio né l’autorizzazione ad alterare un dato. Seleziona proprietà scrivibili e valida i valori.

## Prova a cambiare il caso

La sola assegnazione dinamica conferma che il nuovo Timeout sia stato persistito?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 4. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You need to dynamically set a property on an object. Consider:

set obj = ##class(App.Config).%New()
set propName = "Timeout"
set $PROPERTY(obj, propName) = 30
write obj.Timeout

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-12-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** 30

SET $PROPERTY(obj, propName) \= value dynamically sets a property by name, similar to how SET $PIECE modifies a string. Since propName\="Timeout", this is equivalent to SET obj.Timeout \= 30\. Reading obj.Timeout then returns 30\. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fproperty))

</details>
