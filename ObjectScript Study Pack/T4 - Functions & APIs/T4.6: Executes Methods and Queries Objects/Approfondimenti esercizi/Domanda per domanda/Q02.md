# T4.6 · Q02 — Nome breve e qualificato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-2-single>)

## Il passaggio che risolve l’esercizio

%ClassName(0) produce Invoice, mentre con uno produce MyApp.Invoice.

## Che cosa insegna in più

Il nome breve può collidere fra package. Usa il nome qualificato quando l’identità deve essere non ambigua.

## Prova a cambiare il caso

Billing.Invoice e MyApp.Invoice sono distinguibili dal solo nome breve?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

Visual connection: Core mechanisms, panel 1; Further insights, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You need to inspect the class of an object at runtime. Consider:

set obj = ##class(MyApp.Invoice).%New()
write obj.%ClassName(0), " / ", obj.%ClassName(1)

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-2-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Invoice / MyApp.Invoice

%ClassName(0) returns the short (unqualified) class name: "Invoice". %ClassName(1) returns the full package-qualified class name: "MyApp.Invoice". The argument controls whether the package prefix is included. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_mclassname))

</details>
