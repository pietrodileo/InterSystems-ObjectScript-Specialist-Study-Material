# T4.6 · Q07 — Accesso dinamico a una proprietà

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-7-single>)

## Il passaggio che risolve l’esercizio

PROPERTY legge Name perché il nome della proprietà è il dato contenuto in propName.

## Che cosa insegna in più

L’accesso dinamico deve rispettare le proprietà consentite dall’interfaccia; un nome proveniente dall’esterno può esporre campi non previsti.

## Prova a cambiare il caso

Per un endpoint generico basta che la proprietà esista per restituirla a ogni utente?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

## Testo dell’esercizio

```text
You are building a generic data exporter that reads property values dynamically. Consider:

set obj = ##class(User.Person).%New()
set obj.Name = "Alice"
set propName = "Name"
write $PROPERTY(obj, propName)

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-7-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** Alice

$PROPERTY(obj, propName) dynamically accesses a property by name. Since propName\="Name", this is equivalent to obj.Name, which returns "Alice". This is useful for generic code that processes different classes with different property names. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fproperty))

</details>
