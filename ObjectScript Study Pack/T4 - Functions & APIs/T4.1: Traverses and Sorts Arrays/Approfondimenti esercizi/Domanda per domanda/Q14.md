# T4.1 · Q14 — Ricreare i figli dopo KILL

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-14-single>)

## Il passaggio che risolve l’esercizio

KILL rimuove db e discendenti; i SET successivi ricreano solo host e port. Il contenitore torna a $DATA=10.

## Che cosa insegna in più

Per capire lo stato finale considera le scritture dopo la cancellazione, non soltanto l’effetto del KILL.

## Prova a cambiare il caso

La vecchia stringa assegnata al nodo db ricompare quando ricrei host?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 3. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You are verifying that a configuration node was properly cleaned up. Consider:

kill ^config("db")
set ^config("db","host") = "localhost"
set ^config("db","port") = 1972

write $DATA(^config("db"))

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-14-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** 10

After KILL ^config("db"), the node and all descendants are removed. Then two child nodes are created under ^config("db"), but ^config("db") itself is never given a value. So $DATA returns 10: no value, but has descendants. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fdata))

</details>
