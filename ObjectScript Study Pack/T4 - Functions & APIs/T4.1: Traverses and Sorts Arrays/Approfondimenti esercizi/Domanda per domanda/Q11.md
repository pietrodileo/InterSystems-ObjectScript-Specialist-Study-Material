# T4.1 · Q11 — Refuso nel nome della variabile

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

Il cursore assegnato è key; ordKey non viene assegnato e genera l’errore prima del risultato atteso.

## Che cosa insegna in più

La scansione può essere perfettamente corretta mentre la stampa usa un identificatore diverso. Segui assegnazioni e letture della variabile segnalata.

## Prova a cambiare il caso

Inizializzare ordKey a vuoto corregge davvero il messaggio Order?

<details>
<summary>Ragionamento e risposta</summary>

No: eliminerebbe l’errore ma stamperebbe la variabile sbagliata.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 4. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You are building an order processing routine. Consider the following code:

set orders(1001,"item") = "Widget"
set orders(1001,"qty") = 5
set orders(1002,"item") = "Gadget"
set orders(1002,"qty") = 3

set key = ""
for {
  set key = $ORDER(orders(key))
  quit:key=""
  write "Order: ", ordKey, !
  write "  Item: ", orders(key,"item"), !
}

What happens when this code runs?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** \<UNDEFINED\> error because ordKey was never set

The loop uses the variable ordKey in the Write statement, but ordKey was never assigned a value. The correct variable should be key (which is set by $ORDER). This is a common typo bug that causes an \<UNDEFINED\> \*ordKey error at runtime. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RERR_gen#RERR_UNDEFINED))

</details>
