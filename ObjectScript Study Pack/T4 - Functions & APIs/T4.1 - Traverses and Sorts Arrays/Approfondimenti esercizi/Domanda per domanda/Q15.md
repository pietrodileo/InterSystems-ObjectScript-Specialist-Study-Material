# T4.1 · Q15 — Sentinel prima della dereferenziazione

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-15-single>)

## Il passaggio che risolve l’esercizio

Dopo 1 e 2, la terza chiamata trova la fine e restituisce la stringa vuota.

## Che cosa insegna in più

Controlla la fine immediatamente dopo l’avanzamento. Usare il sentinel come chiave in una lettura può creare un errore o un accesso non voluto.

## Prova a cambiare il caso

Dopo l’esaurimento è corretto leggere arr(key) senza un controllo?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 4. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
What is the output of the following code?

kill arr
set arr(1) = "one"
set arr(2) = "two"
set key = ""
set key = $ORDER(arr(key))
set key = $ORDER(arr(key))
set key = $ORDER(arr(key))
write key
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-15-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** "" (empty string)

Starting from "", the first $ORDER returns 1, the second returns 2, and the third call (from subscript 2\) returns "" because there are no more subscripts. So key is "" and Write outputs an empty string. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_forder))

</details>
