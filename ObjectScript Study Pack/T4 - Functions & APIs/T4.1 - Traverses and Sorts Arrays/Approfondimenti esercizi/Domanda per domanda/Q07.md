# T4.1 · Q07 — Chiave e valore nella stessa scansione

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-7-single>)

## Il passaggio che risolve l’esercizio

Il primo risultato è Alice e il terzo argomento riceve il valore 95 del nodo trovato.

## Che cosa insegna in più

Il valore associato non è la prossima chiave. Mantieni nomi distinti per il cursore e per il dato letto.

## Prova a cambiare il caso

Se cambi Alice da 95 a 60, la prima chiave resta Alice?

<details>
<summary>Ragionamento e risposta</summary>

Sì nel contesto testuale mostrato.

</details>

Visual connection: Core mechanisms, panel 3. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You are writing a utility that retrieves both the key and value in a single $ORDER call. Consider:

set scores("Alice") = 95
set scores("Bob") = 87
set scores("Carol") = 92

set key = ""
set key = $ORDER(scores(key), 1, val)
write key, ": ", val

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-7-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** Alice: 95

The third argument of $ORDER receives the data value at the next node. Starting from "", the first subscript in canonical order is "Alice" (A \< B \< C in ASCII). The value 95 is stored in val. Output: "Alice: 95". (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_forder))

</details>
