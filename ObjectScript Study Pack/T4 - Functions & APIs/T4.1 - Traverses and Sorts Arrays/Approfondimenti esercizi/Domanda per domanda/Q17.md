# T4.1 · Q17 — Default di lettura non è scrittura

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-17-single>)

## Il passaggio che risolve l’esercizio

$GET restituisce 30 se timeout non ha un valore, anche quando ha soli discendenti.

## Che cosa insegna in più

Non conclude che il nodo sia stato creato. La fonte confonde #2 con un bitwise: # è il resto della divisione.

## Prova a cambiare il caso

Dopo set value=$GET(node,30), node deve contenere 30?

<details>
<summary>Ragionamento e risposta</summary>

No, il default ha agito sul risultato della lettura.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 3. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You want to safely check whether a global node exists before reading it. Which approach avoids an <UNDEFINED> error?

set value = ^settings("timeout")
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-17-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** set value \= $GET(^settings("timeout"), 30\)

Only $GET safely avoids \<UNDEFINED\> in all cases. While $DATA(^settings("timeout")) returns a truthy value (10) when the node has subnodes but no value at the node itself, the subsequent SET still causes \<UNDEFINED\> because the node has no data. The correct $DATA check would be $DATA(...)#2 (bitwise AND with 2\) to verify the node has a value. $GET(^settings("timeout"),30) safely returns the default value 30 when the node has no value, regardless of subnodes. $ORDER returns the next subscript, not the value. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fget))

</details>
