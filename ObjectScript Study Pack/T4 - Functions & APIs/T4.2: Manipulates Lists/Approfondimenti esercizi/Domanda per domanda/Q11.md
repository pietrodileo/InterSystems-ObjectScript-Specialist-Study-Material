# T4.2 · Q11 — Accessor rigoroso e accessor con default

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

$LIST su un elemento omesso genera NULL VALUE; LISTGET consente una scelta di fallback.

## Che cosa insegna in più

Il comportamento corretto dipende dal contratto: un campo obbligatorio mancante può meritare un errore, non un valore inventato.

## Prova a cambiare il caso

Usare sempre un default rende automaticamente corretti tutti i record incompleti?

<details>
<summary>Ragionamento e risposta</summary>

No: può nascondere un problema di dati.

</details>

## Testo dell’esercizio

```text
A developer reports that accessing a null list element throws an error. Consider:

set x = $LISTBUILD("A",,"C")
write $LIST(x, 2)

What happens?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** It throws a \<NULL VALUE\> error

Position 2 in $LB("A",,"C") is undefined (null). Unlike $LISTGET which returns a default value for undefined elements, $LIST throws a \<NULL VALUE\> error. Use $LISTGET with a default value to safely access elements that might be null. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_flist))

</details>
