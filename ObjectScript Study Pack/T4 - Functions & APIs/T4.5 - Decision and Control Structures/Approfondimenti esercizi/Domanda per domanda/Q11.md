# T4.5 · Q11 — Chiamata condizionata e assenza di effetto

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

Il DO è saltato perché x è vuoto; il WRITE successivo produce End.

## Che cosa insegna in più

Il postcondizionale agisce sul comando associato, non sul resto dell’intero metodo.

## Prova a cambiare il caso

Il WRITE End viene saltato perché il DO non è avvenuto?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

Visual connection: Core mechanisms, panel 1; Further insights, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You are testing whether a Do post-conditional skips execution. Consider:

set x = ""
do:x ..MyMethod()
write "End"

ClassMethod MyMethod()
{
  write "Called "
}

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** End

Do:x evaluates x as a Boolean condition. Since x\="" which converts to 0 (false), the DO is not executed and MyMethod is never called. Only "End" is written. An empty string is always false in ObjectScript. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_commands#GCOS_commands_postconditional))

</details>
