# T4.2 · Q15 — Posizione positiva come presenza

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-15-single>)

## Il passaggio che risolve l’esercizio

R05 è al secondo posto; il risultato 2 è vero nel ramo IF. Zero segnala l’assenza.

## Che cosa insegna in più

L’IF funziona qui perché il contratto di LISTFIND usa posizioni positive e zero per non trovato. Non estendere questo modello a DynamicArray a base zero.

## Prova a cambiare il caso

La posizione zero di un DynamicArray rappresenta sempre assenza?

<details>
<summary>Ragionamento e risposta</summary>

No, è il primo elemento valido.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 4. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You are processing a multi-value HL7 field stored as a list. Consider:

set diagnoses = $LISTBUILD("J06.9", "R05", "J20.9", "R50.9")
set pos = $LISTFIND(diagnoses, "R05")
if pos {
  write "Found at position: ", pos
} else {
  write "Not found"
}

What is the output?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-15-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Found at position: 2

$LISTFIND returns the 1-based position of the element "R05" in the list. It is at position 2\. Since 2 is non-zero (truthy), the if branch executes and prints "Found at position: 2". If the element were not in the list, $LISTFIND would return 0 (falsy). (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_flistfind))

</details>
