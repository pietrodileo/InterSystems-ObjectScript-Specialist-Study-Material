# T4.2 · Q01 — Indice di posizione e cursore opaco

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

$LISTGET usa la posizione 3 a base uno e restituisce C. $LISTNEXT richiede invece uno stato di scansione.

## Che cosa insegna in più

Non usare il puntatore di iterazione come se fosse un numero di elemento. Le interfacce espongono due concetti diversi.

## Prova a cambiare il caso

Per prendere il primo elemento con LISTGET usi zero?

<details>
<summary>Ragionamento e risposta</summary>

No, usi uno.

</details>

## Testo dell’esercizio

```text
Consider the following list:

set x = $LB("A", "B", "C")

How do you retrieve the third element in this list?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** set y \= $LISTGET(x, 3, "default value")

$LISTGET uses 1-based indexing. $LISTGET(x, 3, "default value") returns the element at position 3, which is "C". The third argument is a default value returned only if the position is undefined. $LISTNEXT is an iteration function with different syntax (it takes a pointer, not a position). (Reference: InterSystems Practice Q15; [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_flistget))

</details>
