# T4.4 · Q10 — Parse di una data

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-10-single>)

## Il passaggio che risolve l’esercizio

ZDATEH con formato tre converte YYYY-MM-DD in giorno logico.

## Che cosa insegna in più

Un formato esplicito evita ambiguità fra giorno e mese. Considera anche il comportamento su date non valide prima di usare input esterni.

## Prova a cambiare il caso

2026-03-05 è interpretato come 3 maggio nel formato tre?

<details>
<summary>Ragionamento e risposta</summary>

No, è il 5 marzo.

</details>

Visual connection: Core mechanisms, panel 3; Further insights, panel 3. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
You are converting an ODBC date string to $HOROLOG format. Consider:

set hDate = $ZDATEH("2026-03-05", 3)

What does hDate contain?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-10-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** An integer representing days since December 31, 1840

$ZDATEH is the inverse of $ZDATE \- it converts a date string to a $HOROLOG date value. Format 3 \= YYYY-MM-DD (ODBC/ISO). It returns an integer representing days since December 31, 1840, which can be used for date arithmetic. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fzdateh))

</details>
