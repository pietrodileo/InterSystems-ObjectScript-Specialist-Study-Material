# T4.5 · Q01 — Postcondizionale e ramo saltato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

SET viene eseguito quando GET(person) è vuoto, sia per variabile mancante sia per stringa vuota.

## Che cosa insegna in più

Quando la condizione è falsa, phone non viene assegnato da questa riga: può conservare un valore precedente o restare indefinito.

## Prova a cambiare il caso

Se person è valorizzato ma phone manca, la riga garantisce un phone leggibile?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

Visual connection: Core mechanisms, panel 1; Further insights, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
While reviewing code you notice the following statement:

set:$GET(person)="" phone = "Unknown"

Which of the following best describes what this line does?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** The assignment executes only when person is undefined or holds an empty string; in that case phone is set to "Unknown". Otherwise the line is skipped.

The post-conditional Set:condition executes the SET command only when the condition is true. $GET(person) returns "" if person is undefined OR if it explicitly holds "". So $GET(person)\="" is true in both cases, and phone gets set to "Unknown". If person has any non-empty value, the entire SET is skipped. (Reference: InterSystems Practice Q18; [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_commands#GCOS_commands_postconditional))

</details>
