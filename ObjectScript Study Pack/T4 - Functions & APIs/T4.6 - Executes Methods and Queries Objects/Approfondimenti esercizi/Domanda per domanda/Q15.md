# T4.6 · Q15 — Routing configurabile con confini chiari

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-15-single>)

## Il passaggio che risolve l’esercizio

La tabella handlers associa email a App.EmailHandler e la chiamata dinamica esegue Process su quella classe.

## Che cosa insegna in più

Il routing è una selezione di capacità. Controlla chi può modificare la tabella e che tutti i target rispettino la stessa firma e gestione degli errori.

## Prova a cambiare il caso

Un handler con firma incompatibile viene adattato automaticamente dal dispatch?

<details>
<summary>Ragionamento e risposta</summary>

No.

</details>

## Testo dell’esercizio

```text
A routing engine dispatches requests to handler classes. Consider:

set handlers("email") = "App.EmailHandler"
set handlers("sms") = "App.SmsHandler"

set type = "email"
set className = handlers(type)
set result = $CLASSMETHOD(className, "Process", "Hello World")

Which statement best describes what happens?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-15-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: A.** It calls ##class(App.EmailHandler).Process("Hello World") dynamically

$CLASSMETHOD takes a class name (string) and method name, then invokes the class method. The class name can come from any expression, including an array lookup. className resolves to "App.EmailHandler", so this is equivalent to ##class(App.EmailHandler).Process("Hello World"). This pattern enables flexible plugin/routing architectures. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_fclassmethod))

</details>
