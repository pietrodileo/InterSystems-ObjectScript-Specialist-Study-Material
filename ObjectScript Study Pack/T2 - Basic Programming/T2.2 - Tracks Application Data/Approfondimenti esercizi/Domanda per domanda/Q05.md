# T2.2 · Q05 — Diagnostica specifica del componente

## Il passaggio che risolve l’esercizio

Il quiz attribuisce a ^%ISCLOG una scala universale: non assumere che ogni componente interpreti lo stesso valore nello stesso modo.

## Che cosa insegna in più

Consulta il logging della tecnologia concreta e annota configurazione precedente, volume e destinazione. Un flag globale non è una specifica completa di tutti gli eventi.

## Prova a cambiare il caso

Per diagnosticare un client HTTP, basta sapere che un altro componente usa ISCLOG=3?

<details>
<summary>Ragionamento e risposta</summary>

No: verifica le istruzioni del componente interessato.

</details>

## Testo dell’esercizio

```text
A production support engineer needs to enable diagnostic logging for troubleshooting a web service integration. They execute:

SET ^%ISCLOG = 3

What effect does this have?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-5-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Enables the built-in diagnostic logging facility at the most verbose level, recording all diagnostic events with timestamps

^%ISCLOG is a built-in diagnostic logging global used by InterSystems components (Interoperability productions, web services, etc.). Level 3 is the most verbose: 0\=disabled, 1\=errors only, 2\=warnings and errors, 3\=all messages. Remember to set it back to 0 after troubleshooting, as verbose logging impacts performance and consumes disk space. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCM_perfmon))

</details>
