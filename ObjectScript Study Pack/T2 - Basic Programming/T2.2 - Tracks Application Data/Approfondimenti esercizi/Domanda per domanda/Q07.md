# T2.2 · Q07 — Ordine delle chiavi del log

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-7-single>)

## Il passaggio che risolve l’esercizio

Le chiavi numeriche canoniche 1, 2 e 10 vengono visitate in ordine numerico, non lessicografico.

## Che cosa insegna in più

La chiave definisce l’ordine di scansione, mentre il testo della voce non influisce su $ORDER.

## Prova a cambiare il caso

Cambiare Complete in Alpha sposta l’ID 10 prima dell’ID 2?

<details>
<summary>Ragionamento e risposta</summary>

No: non stai ordinando i valori.

</details>

## Testo dell’esercizio

```text
A developer wants to iterate through all top-level subscripts of a global and print each value. They write:

SET key = ""
FOR {
  SET key = $ORDER(^Log(key))
  QUIT:key=""
  WRITE key, ": ", ^Log(key), !
}

The global contains:
^Log(1) = "Started"
^Log(2) = "Processing"
^Log(10) = "Complete"

In what order are the entries printed?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-7-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** 1, 2, 10 (numeric/canonical order)

$ORDER traverses subscripts in canonical (collation) order. For numeric subscripts, this is numeric order: 1, 2, 10\. Canonical order sorts numbers before strings, and numbers are sorted by numeric value (not lexicographically). This is why 10 comes after 2, not between 1 and 2\. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_forder))

</details>
