# T2.2 · Q01 — PPG e durata del log

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

^||queryLog appartiene al processo ed è eliminato alla sua fine. Il nome log non ne rende duratura la conservazione.

## Che cosa insegna in più

Processo e richiesta web possono avere vite diverse. Per un audit consultabile dopo l’uscita non basta scegliere un contenitore temporaneo isolato.

## Prova a cambiare il caso

Un nuovo processo può leggere quel log dopo la chiusura del precedente?

<details>
<summary>Ragionamento e risposta</summary>

No: non è un archivio condiviso persistente.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 2. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
While reviewing an application's code, you come across the following line:

set ^||queryLog = $ZTS_" Update Successful, Row Count "_%ROWCOUNT

Which of the following is true about the queryLog variable?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: D.** queryLog is a process private global. It is only visible to the process that instantiates it and it gets cleaned up when the process ends.

The ^\|\| prefix designates a process-private global (PPG). ^\|\|queryLog is visible only to the process that created it, cannot be accessed by other processes, and is automatically deleted when the owning process terminates (not when the IRIS instance restarts). PPGs are ideal for temporary working data that should not leak between processes. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GCOS_globals#GCOS_globals_ppg))

</details>
