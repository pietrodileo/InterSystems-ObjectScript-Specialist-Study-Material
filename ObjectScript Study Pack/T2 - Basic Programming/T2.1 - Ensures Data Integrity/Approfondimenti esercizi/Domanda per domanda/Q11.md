# T2.1 · Q11 — Rollback riuscito non significa operazione riuscita

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-11-single>)

## Il passaggio che risolve l’esercizio

Lock e transazione hanno ruoli complementari e il lock viene rilasciato dopo la conclusione transazionale.

## Che cosa insegna in più

Il CATCH del frammento annulla le modifiche ma poi il metodo ritorna $$$OK: nasconde il fallimento. In un metodo annidato va inoltre rispettato il livello transazionale del chiamante.

## Prova a cambiare il caso

Dopo aver catturato un errore e fatto rollback, è corretto restituire sempre successo?

<details>
<summary>Ragionamento e risposta</summary>

No: propaga lo status o l’eccezione appropriati.

</details>

## Testo dell’esercizio

```text
A developer implements pessimistic concurrency for an order processing system:

ClassMethod ProcessOrder(orderId) As %Status
{
  LOCK +^Order(orderId):10
  IF '$TEST QUIT $$$ERROR($$$GeneralError, "Cannot lock order")
  TSTART
  TRY {
    SET ^Order(orderId,"status") = "Processing"
    ; ... complex business logic ...
    TCOMMIT
  } CATCH ex {
    TROLLBACK
  }
  LOCK -^Order(orderId)
  QUIT $$$OK
}

Which statement best describes this implementation?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-11-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** This is correct: the lock prevents concurrent access, the transaction ensures atomicity, and the lock is released after the transaction completes

This is a well-structured pessimistic concurrency pattern. The lock is acquired first (with a timeout to avoid indefinite waiting), then a transaction wraps the data changes. On error, TROLLBACK rolls back all changes. The lock is released after the transaction finishes (commit or rollback). Releasing the lock before TCOMMIT would allow another process to see uncommitted data. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=TOS_Transaction))

</details>
