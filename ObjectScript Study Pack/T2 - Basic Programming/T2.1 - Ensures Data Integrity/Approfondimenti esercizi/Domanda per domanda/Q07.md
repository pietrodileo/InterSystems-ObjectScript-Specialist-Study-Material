# T2.1 · Q07 — Compatibilità shared ed exclusive

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-7-single>)

## Il passaggio che risolve l’esercizio

Più lettori che richiedono shared possono coesistere; l’exclusive richiesto per la modifica entra in conflitto con quel gruppo.

## Che cosa insegna in più

Il modello riguarda richieste di lock compatibili: non confondere un lettore cooperativo con un accesso diretto che non chiede lock.

## Prova a cambiare il caso

Due processi con shared devono bloccarsi fra loro nello scenario?

<details>
<summary>Ragionamento e risposta</summary>

No; un terzo con exclusive deve invece attendere la compatibilità.

</details>

## Testo dell’esercizio

```text
Consider the following two code blocks:

Block A:
LOCK +^Order(id)#"S"
; read ^Order(id)
LOCK -^Order(id)#"S"

Block B:
LOCK +^Order(id)
; update ^Order(id)
LOCK -^Order(id)

Which statement is correct about concurrent execution?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-7-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: C.** A process running Block A will be blocked if another process is running Block B, but multiple processes can run Block A concurrently

The #"S" flag acquires a shared lock. Multiple processes can hold shared locks on the same reference simultaneously (for reading). However, a shared lock conflicts with an exclusive lock (Block B uses the default exclusive mode). So Block A will be blocked while Block B holds its exclusive lock. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_clock))

</details>
