# T2.1 · Q06 — Timeout e ramo senza modifica

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-6-single>)

## Il passaggio che risolve l’esercizio

Con :5 il processo attende fino al timeout; $TEST distingue acquisizione e mancata acquisizione. Il codice ritorna l’errore prima del SET.

## Che cosa insegna in più

Controlla $TEST subito dopo il comando rilevante: il ramo che scrive deve essere raggiungibile soltanto dopo l’acquisizione riuscita.

## Prova a cambiare il caso

Se il lock non arriva, un retry può avvenire senza prima modificare la fattura?

<details>
<summary>Ragionamento e risposta</summary>

Sì: il ramo di errore deve aver lasciato intatti quei dati.

</details>

## Testo dell’esercizio

```text
A method attempts to acquire a lock with a timeout:

LOCK +^Invoice(invId):5
IF '$TEST {
  SET sc = $$$ERROR($$$GeneralError, "Lock timeout on Invoice "_invId)
  QUIT sc
}
SET ^Invoice(invId,"status") = "Processing"

Another process already holds LOCK +^Invoice(invId). What happens when this code runs?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-6-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** The process waits up to 5 seconds; if the lock is not acquired, $TEST is set to 0 and the error status is returned

When a LOCK command includes a timeout (the :5 suffix), the process waits up to 5 seconds to acquire the lock. If it cannot, $TEST is set to 0 (failure) and execution continues to the next line. The code then checks '$TEST, finds it true (lock failed), and returns an error status. No exception is thrown. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_clock))

</details>
