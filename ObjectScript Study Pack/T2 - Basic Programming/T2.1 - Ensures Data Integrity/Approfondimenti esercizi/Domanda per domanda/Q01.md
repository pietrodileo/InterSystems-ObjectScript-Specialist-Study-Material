# T2.1 · Q01 — Atomicità di due modifiche

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-1-single>)

## Il passaggio che risolve l’esercizio

TSTART e TCOMMIT racchiudono il trasferimento in un’unità transazionale: il primo SET non deve diventare un’operazione definitiva separata dal secondo.

## Che cosa insegna in più

Il lock risolve una questione diversa, cioè il coordinamento fra processi. Una transazione non sostituisce il protocollo di concorrenza.

## Prova a cambiare il caso

Se altri processi possono cambiare contemporaneamente il saldo, basta aggiungere TSTART?

<details>
<summary>Ragionamento e risposta</summary>

No: serve anche una strategia coerente per gli accessi concorrenti.

</details>

Visual connection: Core mechanisms, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer writes the following method to transfer funds between accounts:

ClassMethod Transfer(from As %Integer, to As %Integer, amt As %Numeric) As %Status
{
  SET ^Account(from) = ^Account(from) - amt
  SET ^Account(to) = ^Account(to) + amt
  QUIT $$$OK
}

During testing, the IRIS instance crashes after the first SET but before the second. Which of the following correctly fixes the method to ensure both operations succeed or fail together?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-1-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Add TSTART before the first SET and TCOMMIT after the second SET

TSTART/TCOMMIT ensures that both global modifications are treated as a single atomic unit. If the process crashes mid-transaction, IRIS automatically rolls back all uncommitted changes. Locks control concurrency but do not provide atomicity. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=TOS_Transaction))

</details>
