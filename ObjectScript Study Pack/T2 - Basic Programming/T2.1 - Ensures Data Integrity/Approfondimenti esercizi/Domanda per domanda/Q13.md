# T2.1 · Q13 — LOCK semplice sostituisce l’insieme

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-13-single>)

## Il passaggio che risolve l’esercizio

Dopo +Order(1) e +Order(2), LOCK Order(3) senza più rilascia i precedenti e acquisisce il nuovo.

## Che cosa insegna in più

Un helper che usa un lock semplice può interferire con lock posseduti dal chiamante. Il segno cambia un effetto globale sullo stato del processo.

## Prova a cambiare il caso

La sequenza garantisce che Order(1) resti protetto fino alla fine?

<details>
<summary>Ragionamento e risposta</summary>

No, il lock semplice successivo lo rilascia.

</details>

Visual connection: Core mechanisms, panel 3. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
Consider the following code:

LOCK +^Order(1)
LOCK +^Order(2)
LOCK ^Order(3)

After this code executes, which locks does the process hold?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-13-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Only ^Order(3)

LOCK \+^Order(1) acquires an incremental lock. LOCK \+^Order(2) adds another incremental lock. But LOCK ^Order(3) (without the \+ prefix) is a simple lock: it first releases ALL previously held locks, then acquires only ^Order(3). After execution, only ^Order(3) is held. This is why incremental locks (LOCK \+/-) should be used inside transactions rather than simple LOCK. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_clock))

</details>
