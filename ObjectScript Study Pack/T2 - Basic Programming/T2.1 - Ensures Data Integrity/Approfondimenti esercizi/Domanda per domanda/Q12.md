# T2.1 · Q12 — Lock aggiuntivo e rilascio mirato

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-12-single>)

## Il passaggio che risolve l’esercizio

Il lock semplice su Patient definisce l’insieme corrente; +Appointment lo amplia e -Appointment lo riduce. Resta Patient.

## Che cosa insegna in più

Leggi l’intera sequenza come trasformazione di un insieme, non ogni riga isolata. Un rilascio mirato non equivale a liberare ogni risorsa.

## Prova a cambiare il caso

Se dopo il rilascio di Appointment vuoi liberare Patient, serve un’azione esplicita?

<details>
<summary>Ragionamento e risposta</summary>

Sì, nel protocollo di cleanup previsto.

</details>

## Testo dell’esercizio

```text
Consider the following code:

LOCK ^Patient(42)
SET ^Patient(42,"name") = "Jones"
LOCK +^Appointment(100)
SET ^Appointment(100,"patient") = 42
LOCK -^Appointment(100)

After this code executes, which locks does the process still hold?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-12-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** Only ^Patient(42)

LOCK ^Patient(42) (without \+) is a simple lock: it releases ALL previously held locks, then acquires ^Patient(42). LOCK \+^Appointment(100) is incremental and adds to existing locks without releasing ^Patient(42). LOCK -^Appointment(100) releases the incremental lock on ^Appointment(100). After execution, only ^Patient(42) is still held. This demonstrates the important difference between simple LOCK (releases all prior locks) and incremental LOCK \+/- (adds/removes individual locks). (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=RCOS_clock))

</details>
