# T2.3 · Q14 — Host variable e struttura SQL

[Tutte le domande](README.md) · [Approfondimenti del capitolo](../README.md) · [Domanda originale](<../../quiz.md#question-14-single>)

## Il passaggio che risolve l’esercizio

:status passa un valore alla struttura Embedded SQL: un testo malevolo viene usato come dato del confronto.

## Che cosa insegna in più

Injection e autorizzazione sono due domande distinte. Una query parametrizzata può comunque essere eseguita da un servizio che concede troppo accesso.

## Prova a cambiare il caso

Un input contenente OR 1=1 modifica il WHERE se resta un valore host?

<details>
<summary>Ragionamento e risposta</summary>

No, non diventa codice SQL.

</details>

Visual connection: Core mechanisms, panel 2; Further insights, panel 1. See the [English diagrams and panel explanations](../tavole-esercizi.md).

## Testo dell’esercizio

```text
A developer writes a search method that accepts user input:

ClassMethod FindOrders(status As %String) As %Status
{
  &sql(DECLARE OrderCursor CURSOR FOR
    SELECT OrderId, Total FROM Orders WHERE Status = :status)
  &sql(OPEN OrderCursor)
  ; process results
}

Is this code vulnerable to SQL injection? Why or why not?
```

[Apri il quiz con tutte le opzioni](<../../quiz.md#question-14-single>).

<details>
<summary>Risposta e spiegazione originali della fonte (inglese)</summary>

**Correct answer: B.** No, because Embedded SQL with host variables (:status) treats the input as a data value, not as SQL code, preventing injection

Embedded SQL host variables (prefixed with :) are treated as parameterized input. The value of the ObjectScript variable 'status' is passed as data, not interpreted as SQL code. This provides the same SQL injection protection as ? parameters in Dynamic SQL. Even if the user passes malicious input like ' OR 1\=1 --, it is treated as a literal string value. (Reference: [Reference](https://docs.intersystems.com/irislatest/csp/docbook/DocBook.UI.Page.cls?KEY=GSQL_esql))

</details>
